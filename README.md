# Online Booking — Medical Appointment System

REST API и веб-приложение для управления медицинским центром и записи пациентов на приём.

Система позволяет управлять пациентами, врачами и медицинскими услугами, назначать услуги врачам, настраивать рабочее расписание и создавать записи на приём с проверкой доступности врача.

## Установка

### Клонирование репозитория

```bash
git clone https://github.com/Bessia56/Online_booking.git
cd Online_booking
npm install
```

## Настройка

Для работы проекта используется PostgreSQL.

Создайте базу данных Online_booking и скопируйте файл .env.example в .env в корне проекта:

```bash
cp .env.example .env
```
Укажите параметры подключения к базе данных в .env:

```env
DB_HOST=localhost
DB_PORT=5432
DB_NAME=Online_booking
DB_USER=postgres
DB_PASSWORD=your_password
```

## Создание таблиц

Для создания таблиц, связей, индексов и триггеров выполните SQL-скрипт:

```bash
psql -U postgres -d Online_booking -f database/init.sql
```

## Запуск

```bash
npm start
```


После запуска веб-интерфейс доступен по адресу:

```text
http://localhost:3000
```

## API

### Пациенты

#### Создание пациента

>Создаёт нового пациента. Перед созданием проверяется, зарегистрирован ли пациент с таким номером телефона.

**Запрос**

- **Метод:** `POST`
- **Путь:** `/patients`
- **Тело запроса (JSON):**

```json
{
  "first_name": "Иван",
  "last_name": "Иванов",
  "phone": "+79991234567",
  "email": "ivan@example.com"
}
```

**Допустимые значения**

| Поле | Тип | Обязательное | Значения |
|---|---|---|---|
| `first_name` | string | Да | Имя, максимум 100 символов |
| `last_name` | string | Да | Фамилия, максимум 100 символов |
| `phone` | string | Да | Номер телефона, максимум 20 символов |
| `email` | string / `null` | Нет | Корректный email, максимум 255 символов |

**Пример запроса**

```bash
curl -X POST http://localhost:3000/patients \
  -H "Content-Type: application/json" \
  -d '{"first_name":"Иван","last_name":"Иванов","phone":"+79991234567","email":"ivan@example.com"}'
```

**Успешный ответ**

Код: `201 Created`. Возвращается созданная запись пациента с полями, сформированными базой данных.

**Возможные ошибки**

| Код | Описание |
|---|---|
| `400` | Некорректные данные или пациент с таким номером телефона уже существует |
| `409` | Нарушено ограничение базы данных |

#### Получение списка врачей

>Возвращает список врачей. Поддерживается фильтрация по активности.

**Запрос**

- **Метод:** `GET`
- **Путь:** `/doctors`
- **Query-параметр:** `is_active` — необязательный, принимает `true` или `false`
- **Тело запроса:** отсутствует

Если параметр не передан, возвращаются все врачи.

**Примеры запросов**

```bash

curl "http://localhost:3000/doctors?is_active=false"
```

**Успешный ответ**

`200 OK` — возвращается массив врачей.

**Возможные ошибки**

| Код | Описание |
|---|---|
| `400` | Передано недопустимое значение `is_active` |
| `500` | Внутренняя ошибка сервера |

#### Фильтрация врачей

>Позволяет получить врачей по активности или по оказываемой услуге.

**Запрос**

- **Метод:** `GET`
- **Путь:** `/doctors/filter`
- **Query-параметры:**

| Параметр | Тип | Обязательное | Значения |
|---|---|---|---|
| `is_active` | string | Нет | `true` или `false` |
| `serviceId` | integer | Нет | Положительный ID услуги |

**Примеры запросов**

```bash
curl "http://localhost:3000/doctors/filter?is_active=true"
curl "http://localhost:3000/doctors/filter?serviceId=2"
```

При фильтрации по `serviceId` возвращаются активные врачи, которым назначена активная связь с активной услугой.

**Успешный ответ**

`200 OK` — возвращается массив врачей.

**Возможные ошибки**

| Код | Описание |
|---|---|
| `400` | Некорректное значение `is_active` или `serviceId` |
| `404` | Услуга не найдена или неактивна |
| `500` | Внутренняя ошибка сервера |

### Услуги врачей

Связь врача с услугой хранится в таблице `doctor_services`. Для каждой связи задаётся продолжительность приёма в минутах.

#### Назначение услуги врачу

>Создаёт связь врача с услугой. Врач и услуга должны существовать и быть активными. Если связь ранее была деактивирована, она повторно активируется с указанной продолжительностью.

**Запрос**

- **Метод:** `POST`
- **Путь:** `/doctors/:doctorId/services`
- **Параметр пути:** `doctorId` — идентификатор врача
- **Тело запроса (JSON):**

```json
{
  "serviceId": 2,
  "durationMinutes": 40
}
```

**Допустимые значения**

| Поле | Тип | Обязательное | Значения |
|---|---|---|---|
| `serviceId` | integer | Да | ID существующей активной услуги |
| `durationMinutes` | integer | Да | Положительная продолжительность приёма в минутах |

**Пример запроса**

```bash
curl -X POST http://localhost:3000/doctors/1/services \
  -H "Content-Type: application/json" \
  -d '{"serviceId":2,"durationMinutes":40}'
```

**Успешный ответ**

- `201 Created` — создана новая связь врача и услуги.
- `200 OK` — повторно активирована ранее деактивированная связь.

В обоих случаях возвращается объект связи.

#### Создание рабочего интервала

Добавляет рабочий интервал для врача. Время передаётся в формате `HH:mm`. Новый интервал не должен пересекаться с уже существующими активными интервалами этого дня.

```json
}
```

| Поле | Тип | Обязательное | Значения |

## Обработка ошибок

В приложении используется единый middleware обработки ошибок Express.

Ошибки валидации Yup и ограничения PostgreSQL преобразуются в HTTP-ответы:

| Код HTTP | Условие | Описание |
|---|---|---|
| `400` | Yup `ValidationError` | Некорректные входящие данные |
| `400` | PostgreSQL `23502`, `23514` | Нарушение `NOT NULL` или `CHECK` |
| `409` | PostgreSQL `23505` | Нарушение уникальности `UNIQUE` |
| `409` | PostgreSQL `23503` | Нарушение внешнего ключа `FOREIGN KEY` |
| `404` | Запись не найдена | Запрошенный ресурс отсутствует |
| `500` | Необработанная внутренняя ошибка | Внутренняя ошибка сервера |

Пример ответа при ошибке валидации:

```json
{
  "statusCode": "error",
  "code": 400,
  "message": "Ошибка данных",
  "errors": [
    "Имя обязательно"
  ]
}
```
